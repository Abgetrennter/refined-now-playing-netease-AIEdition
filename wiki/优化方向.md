# 优化方向

> 版本: 2.19.5  
> 最后更新时间: 2025-12-01

基于当前代码库的分析，以下是 Refined Now Playing 未来可能的优化方向和改进建议。

## 1. 性能优化

### 1.1 Canvas 渲染优化
- **现状**: `background.js` 中的 `FluidBackground` 使用了 4 个 Canvas 分块渲染，并配合 SVG Filter。这种方式在部分低端显卡上可能会导致高 GPU 占用。
- **建议**:
  - 考虑使用 **WebGL** (如 `three.js` 或原生 WebGL) 重写流体效果，利用 GPU 的并行计算能力，减少 CPU/GPU 数据传输。
  - 增加“性能模式”检测，在检测到帧率过低时自动降级到静态图片或普通模糊。

### 1.2 歌词列表 DOM 操作
- **现状**: 歌词滚动通过直接修改大量 DOM 元素的 `style` (transform, opacity, filter) 实现。虽然 React 做了 Diff，但频繁的重排重绘仍有开销。
- **建议**:
  - 使用 **Virtual List (虚拟列表)** 技术，仅渲染视口内可见的歌词行，大幅减少 DOM 节点数量。
  - 使用 `will-change` 属性优化关键动画元素的合成层。

## 2. 代码架构重构

### 2.1 `main.js` 瘦身
- **现状**: `main.js` 包含了近 1000 行代码，混合了初始化、DOM 监听、设置逻辑、样式注入等多种职责。
- **建议**:
  - 将设置逻辑 (`initSettings`) 拆分到单独的 `settings-manager.js` 模块。
  - 将 DOM 注入和观察逻辑拆分到 `injector.js`。
  - 引入更完善的状态管理 (如 Redux 或 Context API) 替代散落在各处的全局变量和 Custom Event。

### 2.2 类型系统
- **现状**: 项目目前主要使用原生 JavaScript，缺乏类型检查。
- **建议**:
  - 引入 **TypeScript** (虽然已有 `liblyric/index.ts`，但主逻辑仍是 JS)。添加类型定义可以显著提高代码的可维护性和开发效率，减少运行时错误。

## 3. 功能扩展

### 3.1 更多可视化效果
- **建议**:
  - 引入音频可视化频谱 (Spectrum Visualizer)，作为背景或前景的一部分，与现有的流体效果结合。
  - 支持更多样化的逐字歌词动画预设 (如跳跃、淡入淡出组合)。

### 3.2 社区生态
- **建议**:
  - 开放“主题接口”，允许用户通过 JSON 配置或 CSS 片段分享自己的配色和参数设置。
  - 支持导出/导入设置文件。

## 4. 兼容性增强

### 4.1 国际化 (i18n)
- **现状**: 目前的界面文本（如设置菜单）硬编码为中文。
- **建议**:
  - 建立 i18n 机制，提取所有文本资源，支持英文等多语言切换，以便服务更多 BetterNCM 用户。

### 4.2 错误处理
- **建议**:
  - 增强 `lyric-provider.js` 中的错误捕获，当歌词解析失败或网络请求异常时，提供更友好的 UI 提示而非静默失败。
